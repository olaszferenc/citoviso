## Elvégezve
- `migrations/0081_mms_outbox.sql` + `src/db/schema.ts` `MmsOutboxTable` — KÜLÖN tábla (az SMS-út bájtra ugyanaz marad),
  a JPEG bytea-ként a sorban, `unknown` állapot, prospectenként egy függő MMS (részleges egyedi index). Dev DB-re alkalmazva.
- `src/mms/sender.ts`: `toMmsJpeg`/`ensureMmsJpeg` sharp-pal (1280 px, 85→−10 lépcső, ≤290 KB, alfa fehérre, plafon fölött dob);
  `queue` provider; `sendMmsViaCli` + `cliErrorDetail` exportálva a relaynek.
- `src/mms/relayQueue.ts` (szerver): `pullMms` (EGY üzenet; beragadt `sending` → `unknown` + riasztás, NEM küldi újra),
  `ackMms` (ok → `sent` + `mms_sent_at` + a pár SMS-fele; foglalt modem → vissza, kísérlet visszajár; 3 bukás → `failed` + riasztás).
- `src/server/public.ts`: `/api/mms-relay/pull|ack` (ugyanaz a `SMS_RELAY_SECRET`).
- `src/mms/relayClient.ts` + `scripts/mms-relay.mts` (dev gép): napló (`outbox-mms/relay-journal.json`) az ack ELŐTT, utólagos nyugtázás.
- `src/outreach/sendOutreachPair.ts`: queue módban csak sorba tesz (nincs claim), `pairJobState` a sorból olvas; `src/console/server.ts` ezt hívja.
- `deploy/systemd/citoviso-mms-relay.{service,timer}` + `targets.json` (dev).
- Őr: `scripts/mms-relay-check.mts` (új, 32 állítás; negatív kontroll: a beragadt sor visszasorolása → piros) +
  `scripts/mms-preview-gate-check.mts` ⑨ (sharp) · `hooks/pre-commit` bekötés · `docs/mms-send.md`.

## Nyitott / deploy után
- Élesen `MMS_PROVIDER=queue` az .env-be (a deployjal együtt, a tulaj engedélyével).
- Dev gépen: `citoviso-mms-relay.timer` telepítése + engedélyezése (a fő fából; `SMS_RELAY_URL`/`SECRET` már ott van).
- A pár SMS-fele az ack pillanatában indul; ha az MMS 20:00 után ér ki, a kísérő SMS az ablak miatt elbukik → törött pár.
  Élesen nincs `pair-repair` időzítő (dev-only) → a konzol piros jelzése + kézi újraküldés marad.
